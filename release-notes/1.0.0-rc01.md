# Web Editor 1.0.0-rc01 — Release Notes

**Released:** 2026-11-22 · **Pre-release** (`npm install @keenmate/web-editor@rc`)

This is the **first release** of `@keenmate/web-editor` — no earlier version is on npm, so there is nothing to
upgrade from. These notes are a first-release guide: what the package is, what it needs, and what it ships.
Code written against an unpublished development build (a `file:` link or a git checkout) should read the
BREAKING entries in the CHANGELOG — they record renames made during development, and none of them has an alias.

`<km-editor>` is a framework-agnostic WYSIWYG / Markdown editor on [ProseMirror](https://prosemirror.net/), built
on `@keenmate/web-components-core` like every Keenmate component: one document with Markdown, HTML and JSON as
import / export lenses, four view modes, a command-driven toolbar / selection toolbar / context menu, a plugin and
pipeline system, form participation, localization, theming through the shared `--base-*` contract, and a headless
`EditorEngine` for building your own UI.

The exhaustive, per-change list is in
[`CHANGELOG.md`](https://github.com/Keenmate/web-editor/blob/prod/CHANGELOG.md) (section
1.0.0-rc01); this document is the upgrade guide and the highlights.

## New features — the element

### One document, three lenses

`<km-editor>` holds ONE ProseMirror document; `content-format` (`markdown` | `html` | `json`) is only the lens for
I/O. The `value` attribute is the initial content (property `defaultValue`); the `value` property is the live
content in the active format. `getMarkdown()` / `getHTML()` / `getJSON()` read a fixed format, `setValue(value,
format?, { isSilent })` replaces the document. HTML and JSON round-trip losslessly; Markdown import does not parse
tables back into table nodes (export writes them as raw HTML).

```html
<km-editor value="# Hello" content-format="markdown" toolbar="top" statusbar="bottom"></km-editor>
```

### View modes

`view-mode`: `edit`, `split` (editor + a live Markdown / HTML / JSON output with tabs), `preview` (read-only) and
`inline` (a floating card that tracks the page element named by `anchor`). The document, selection and undo
history survive a mode switch and a DOM move. `setViewMode(mode, { isSilent })` and the toolbar's Edit / Split /
Preview items fire `view-mode-change` `{ viewMode, oldViewMode, source }`; assigning `viewMode` is silent. The split
view stacks below 720 px of the EDITOR's own width (container query).

### Events and state

Events bubble (not composed) and have a camelCase twin called with the same detail: `change` `{ value,
contentFormat }`, `ready`, `view-mode-change`, `lock-change` `{ isLocked }`, `value-format-error`, `action`.
Assigning a value / state property never fires an event (like a native `input.value`); methods and user
interaction do. Core lifecycle applies: `defer` / `release()`, `isReady` / `whenReady()`, `destroy()`.

### Read-only and disabled

`readonly` (`isReadonly`) — the content can't change, but the surface stays focusable and Ctrl/⌘+A selects it for
copying; the view-mode toolbar group stays. `disabled` (`isDisabled`, or an ancestor `<fieldset disabled>`) — no
interaction, the surface is `inert`, the toolbar hides. Both reflect, with native presence semantics.

### Responsive rules

Core's shared responsive rules (`device` / `breakpoint` / `container` maps or a callback), page-wide, per tag
(`window.components['km-editor'].responsive*`) or per instance (`responsive` attribute / property,
`responsiveCallback`).

## New features — toolbars, menus and items

- **Static toolbar** docked to any edge (`toolbar="top|bottom|start|end|none"`), organised in tool groups; its last
  group is the Edit / Split / Preview radio group. A **selection toolbar** floats over a selection; a **right-click
  context menu** is core `openMenu()` (`menu-presentation="auto|floating|sheet|drawer"` — a bottom sheet on a
  phone by default — and `menu-side`). A **status bar** (`statusbar="none|top|bottom|both"`) shows live word /
  character counts and plugin items.
- **Items are core action items** (`EditorActionItem`: `action`, `id`, `text`, `icon`, `tooltip`, `shortcut`,
  `isToggled`, `isDisabled`, `get*Callback(ctx)`, `onClick`), a command id string is shorthand. Every click runs
  `beforeActionCallback` (`false` cancels) → the item's `onClick` → the command → the `action` event.
- **Tooltips** are core `createTooltip` (themed, shown on keyboard focus, `aria-describedby`); shortcuts display
  through core `formatShortcut` (`⇧⌘Z` on Apple platforms).
- **Prompts and confirmations** (link URL, image URL / alt text, code-block language, a pipeline stage's
  confirmation) are core `/dialog` modals — never `window.prompt` / `confirm`; a bottom sheet on a phone.

## New features — plugins and pipelines

- **Plugins** — `definePlugin({ nodes, marks, markdown, commands, keymap, pmPlugins, toolbarGroups,
  selectionItems, menuItems, statusItems, setup, destroy, dependencies })`; the engine assembles schema, commands,
  keymaps, Markdown I/O and chrome items in dependency order, and throws at assembly for a node / mark without a
  Markdown serializer. First-party: `linkPlugin`, `imagePlugin`, `tablePlugin`, `codeHighlightPlugin`
  (`defaultPlugins()`), plus the cloud-image `imageBrowserPlugin({ upload })` and `imageBase64Plugin`. Assign
  `el.plugins = [...defaultPlugins(), myPlugin]`; a set that fails to assemble keeps the previous editor.
- **Commands are pipelines** — a toolbar button, a key binding and `controller.runCommand(name)` fire the same named
  pipeline; plugins splice stages into any pipeline by anchor. Deferred pipelines get abort / supersede, a pending
  loader (`renderLoadingCallback`, page-wide `window.components.renderLoadingCallback`) that ignores time spent
  waiting in a dialog, an optional lock (`lock-change`), and the `interactionHost` modal bridge. See
  [docs/pipelines](https://github.com/Keenmate/web-editor/blob/prod/docs/pipelines/README.md).

## New features — forms

`name` adds a light-DOM hidden `<input name>` carrying the live content in `content-format`; `form.reset()`
restores `defaultValue` silently; disabled (incl. `<fieldset disabled>`) is not submitted.
`getValueFormatCallback(ctx)` formats only the submitted value (e.g. sanitizing HTML); when it throws the field is
invalid (core `setFormatError`, message `errors.valueFormat`) and `value-format-error` fires.

`required` (`isRequired`) works like a native control's: while the document has no content (no text after
trimming whitespace and no image / table / other non-text node) the field is `validity.valueMissing` (message
`errors.required`, "This field is required.") and the form refuses to submit; read-only / disabled are never
missing. The host gets `aria-required` + `:state(required)` (core), the editing surface `aria-required="true"`.

```html
<form>
  <km-editor name="body" required></km-editor>
  <button>Send</button>
</form>
```

## New features — localization and icons

- **`labels`** (property or JSON attribute) — every UI string under flat `<elementType>.<name>` keys
  (`tooltips.bold`, `ariaLabels.insertLink`, `menuItems.insertTable`, `headers.linkUrl`, `labels.words`, …), partial
  over built-in English. The page-wide dictionary is one flat object in `window.components.locale.labels`
  (`'km-editor.tooltips.bold'`); `translateCallback` (the element's own, then the page-wide one) plugs in an app's
  i18n. `locale` formats the status-bar counts (`Words: 1.234` for `de`).
- **Labels read the spot's context** — a dynamic label passes its values as `{ ctx }`, so templates read
  `{ctx.count}` / `{ctx.languages}` and a `translateCallback` gets `params.ctx`. `ctx.count` is the number the
  text's noun agrees with, so an app's i18n picks the plural form (`t(key, { ...params, count: params.ctx?.count })`);
  the English defaults keep the number after a colon (`Words: 3`). Typed as `StatusCountLabelContext` and
  `CodeLanguageLabelContext`.
- **Icons** — the built-in toolbar icons are inline SVGs (`EDITOR_ICONS`); an item `icon` goes through core
  `renderIcon` (markup → built-in name → `renderIconCallback` → page-wide `window.components.renderIconCallback` →
  icon-font class). Assigning the page-wide icon hook repaints live editors in place.

## New features — theming

- Shadow-DOM scoped, layered stylesheet; every colour is a `--we-*` variable chained to the shared `--base-*`
  contract with `light-dark()` fallbacks, so a `:root` theme reaches the editor. `component-variables.manifest.json`
  (export `@keenmate/web-editor/manifest`) lists every variable.
- Dark mode follows the page (core detection of `data-theme` / `data-bs-theme` / `.dark` on `<html>` / `<body>`);
  force one editor with `<km-editor data-theme="dark">`.
- Custom CSS in the shadow root: `custom-styles` / `getCustomStylesCallback`, plus the page-wide
  `window.components['km-editor'].customStyles`. The context menu takes `--we-context-menu-*` (→ core
  `--km-menu-*`). Stacking uses core's z-index tiers (`--we-popover-z-index`, `--we-tooltip-z-index`).
- Right-to-left: list indent, the code-block label, table headers, the placeholder and side toolbar borders use
  logical CSS.

## New features — accessibility

- The editing surface is a named WAI-ARIA textbox (`role="textbox"`, `aria-multiline`, `aria-readonly` /
  `aria-disabled`); its name comes from `aria-labelledby` / `aria-label` / a `<label for>`, else
  `ariaLabels.editor` ("Rich text editor").
- Keyboard: the static toolbar and the selection toolbar are one tab stop each with arrow keys (core
  `createRovingFocus`); **Alt+F10** jumps from the text into the selection / static toolbar and **Escape** returns;
  **Shift+F10** / the ContextMenu key open the context menu at the caret; Shift+Enter inserts a hard break.
- The split view's output tabs are a WAI-ARIA tab list; view-mode switches are announced through core
  `announce()` (`ariaLabels.viewMode*`; `''` silences one). See
  [docs/accessibility.md](https://github.com/Keenmate/web-editor/blob/prod/docs/accessibility.md).

## New features — building your own UI

`EditorEngine` is the headless core of `<km-editor>`: the ProseMirror view / state, schema, command registry,
pipelines, serialization and a typed event bus — you draw the chrome. It takes the element's settings with the
element's defaults:

```js
import { EditorEngine, defaultPlugins } from '@keenmate/web-editor';

const engine = new EditorEngine(mountElement, { markdown: '# Hi', plugins: defaultPlugins() });
engine.setOptions({ isReadonly: true, locale: 'de' }); // in place — document, selection, undo kept
engine.getOptions().isReadonly;                         // true
```

`setOptions(Partial<EditorEngineOptions>)` applies `isReadonly`, `labels`, `locale`, `translateCallback`,
`interactionHost` live; `plugins` / `prosemirrorPlugins` / `schema` / `host` are construction-only. See
[docs/usage.md → Build your own UI](https://github.com/Keenmate/web-editor/blob/prod/docs/usage.md#build-your-own-ui).
