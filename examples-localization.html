Every UI string of <km-editor> goes through core /locale. Keys are flat <elementType>.<name>. Command keys derive <name> from the command id (insert-code-block → insertCodeBlock) and the element type from where the text is shown: ariaLabels.bold (an icon toolbar button's accessible name), buttons.viewEdit (a text toolbar button), tooltips.bold, menuItems.bold. The named keys (labels.words, headers.codeLanguage, buttons.ok, ariaLabels.formatGroup, …) are DEFAULT_LABELS in src/labels.ts. Per key: the instance labels (short or full km-editor. key) → the element's own translateCallback → the page-wide translateCallback → the page dictionary window.components.locale.labels → the built-in English. The page-wide toggles (LO02, LO03, LO05) change every editor on this page, on purpose.

LO01 · Instance labels

Override texts on ONE element with the labels property (or a JSON labels attribute). Short keys (tooltips.bold, buttons.viewEdit) and a full key (km-editor.labels.words, with its {count} placeholder) both work; every key you leave out stays English. The neighbour editor is untouched. Hover B to see the tooltip.

rendered strings (read from the shadow root)

    

    
el.labels = {
  'tooltips.bold': 'Tučné písmo (Ctrl+B)',      // short key
  'buttons.viewEdit': 'Upravit',
  'km-editor.labels.words': 'Slova: {count}',  // full key
};
// or declaratively
<km-editor labels='{"labels.words": "Slova: {count}"}'></km-editor>









    
LO02 · Page-wide dictionary

    

        One flat dictionary on window.components.locale.labels — the app's translation JSON as loaded, full
        keys 'km-editor.<elementType>.<name>', other components' keys side by side — translates
        every editor on the page at once: toolbar names, the toolbar group name, the view buttons, the status bar and the
        prompts. Click Insert code block (the </> button) to see the translated prompt
        (headers.codeLanguage with its {languages} placeholder, buttons.ok /
        buttons.cancel). Keys an instance set itself (LO01) still win.
    

    

        
    

    

        

            

                
                
            

            

                
                
            

        

        
rendered strings (read from the shadow root)

    

    
// e.g. const labels = await (await fetch('/i18n/cs.json')).json();
window.components.locale = {
  labels: {
    'km-editor.ariaLabels.bold': 'Tučně',
    'km-editor.ariaLabels.italic': 'Kurzíva',
    'km-editor.ariaLabels.formatGroup': 'Formát',
    'km-editor.buttons.viewEdit': 'Upravit',
    'km-editor.labels.words': 'Slova: {count}',
    'km-editor.labels.chars': 'Znaky: {count}',
    'km-editor.headers.codeLanguage': 'Zadejte jazyk ({languages})',
    'km-editor.buttons.ok': 'OK',
    'km-editor.buttons.cancel': 'Zrušit',
    'web-multiselect.placeholders.search': 'Hledat…',   // other components share the same JSON
  },
};









    
LO03 · translateCallback

    

        An app with its own i18n (i18next, FormatJS, …) answers keys through a callback instead of a dictionary. It gets
        { component, key, template, params, locale } — key is the full
        km-editor.<elementType>.<name> — and returns the text, or null = not mine.
        The element's own translateCallback is asked first (German, only ariaLabels.bold and
        labels.words here); its null passes the key on to the page-wide one (a small Slovak
        i18next-like lookup with {{count}}). A key the instance labels set (the second editor's
        labels.words) is never sent to any callback.
    

    

        
        
    

    

        

            

                
                
            

            

                
                
            

        

        
rendered strings (read from the shadow root)

    

    
// an i18next-like lookup: a dictionary + t(key, params)
const sk = {
  'km-editor.ariaLabels.bold': 'Tučné',
  'km-editor.ariaLabels.italic': 'Kurzíva',
  'km-editor.labels.words': 'Slová: {{count}}',
  'km-editor.labels.chars': 'Znaky: {{count}}',
};
const t = (key, params) => sk[key].replace(/\{\{(\w+)\}\}/g, (_, p) => params?.[p] ?? '');

// page-wide — every component on the page
window.components.locale = { translateCallback: ({ key, params }) => (key in sk ? t(key, params) : null) };

// one element — asked BEFORE the page-wide callback; null = not mine
el.translateCallback = ({ key, params }) => {
  if (key === 'km-editor.ariaLabels.bold') return 'Fett';
  if (key === 'km-editor.labels.words') return `Wörter: ${params.count}`;
  return null;
};









    
LO04 · Screen-reader name / tooltip follow

    

        An ariaLabels.x / tooltips.x nobody set takes the customized key of the same
        <name>, so translating one string of a pair translates its twin. The view buttons are TEXT
        buttons: translate their caption buttons.viewSplit and the tooltip (tooltips.viewSplit,
        nobody set) follows. The B button is an ICON button whose only visible text is its tooltip: translate
        tooltips.bold and its accessible name ariaLabels.bold (nobody set) follows. The box reads
        the button text, the tooltip (data-tooltip) and the aria-label from the shadow root.
    

    

        
    

    

        
        
visible text / tooltip / accessible name

    

    
el.labels = { 'buttons.viewSplit': 'Rozdělit', 'tooltips.bold': 'Tučně' };
// → the Split button reads "Rozdělit" AND its tooltip is "Rozdělit" (tooltips.viewSplit was never set)
// → the B button's tooltip is "Tučně" AND its aria-label is "Tučně" (ariaLabels.bold was never set)
// an explicitly set ariaLabels.x / tooltips.x always wins over the twin









    
LO05 · locale + formatting

    

        The numbers in labels — the {count} of labels.words / labels.chars in the status
        bar — are formatted for the element's locale input → the page language
        window.components.locale.locale → the browser. The editor formats no dates — numbers only. A
        translateCallback gets the raw number (params.count === 1234) and the resolved
        locale, so ICU / i18next plural rules work. The editor below holds 1,234 words.
    

    
page locale
        
        
        
        
    

    
element locale
        
        
        
    

    

        
        
status bar

    

    
window.components.locale = { locale: 'de-DE' };
// "Words: 1.234 / Chars: 2.467"   (cs-CZ: "1 234", en-IN: "1,234")

// one editor, beating the page locale (unset / 'auto' = follow the page)
<km-editor locale="cs" statusbar="bottom"></km-editor>
el.locale = 'de';









    
LO06 · shouldEscapeLabels

    

        Not applicable: every editor label is TEXT (textContent / attributes / the tooltip's text — no label is
        an HTML template), so a <b> in a label always shows as characters and
        window.components.security.shouldEscapeLabels changes nothing.
