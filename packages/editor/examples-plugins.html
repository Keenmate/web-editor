Plugins & Pipelines

Compose a custom plugin set on the element, layer toolbar groups by id, and drive the command-triggered cloud-image pipeline — then splice a stage into it from a second plugin without touching the first.

PP01 · Cloud-Image Pipeline

The imageBrowserPlugin declares a deferred, locking pipeline image:browser:pick (pick → upload → insert), fired by the toolbar ☁ button or the one below. It opens a host-provided picker (an interactive stage via the injected InteractionHost), awaits a fake upload, then inserts — the editor is locked for the whole run. Toggle base64 to drop in imageBase64Plugin, which splices a to-base64 stage before insert — the browser plugin is never touched.

Pipeline image:browser:pick — idle

PP02 · Override / Remove by Id

A plugin's toolbarGroups / statusItems are keyed by id: a matching id replaces in place (later plugins win), a new id slots in, and removeToolbarGroups drops one. Toggle a tiny inline plugin that removes the list group and adds a custom status item — the engine rebuilds on the new plugin set and preserves the live content.

PP03 · Cloud Image → Crop → Insert

The real end-to-end image flow, landing in the editor. A second plugin splices an interactive crop stage after upload (and before insert) into image:browser:pick — the browser plugin is never touched. Pick a cloud image, crop it in the dialog, and the cropped image is inserted. The editor is locked for the whole run.

pipeline image:browser:pick — pick → upload → crop → insert
